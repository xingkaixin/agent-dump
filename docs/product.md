# 项目定位与设计原则

本文记录 agent-dump 长期不变的目标、非目标和设计原则，用于判断新需求是否偏离方向。具体模块职责见[架构](architecture.md)，领域术语见 [`CONTEXT.md`](../CONTEXT.md)，可观察行为以 README 为准。

## 1. 定位

agent-dump 是面向个人开发者和 AI Agent 的本地会话工具。它读取本机编程助手已保存的会话记录，提供发现、查询、阅读、导出和汇总能力，不修改来源数据。

两类使用者共用同一个 CLI：

- 开发者：在终端中浏览、搜索、导出过去的会话。
- AI Agent：通过 JSON 输出、退出码和分页游标，有界地读取会话并完成上下文交接或工作汇总。

## 2. 目标

1. **只读访问多个 Provider。** 把各工具私有的文件或数据库映射为统一的 Session facts 和标准化正文。新增 Provider 不改变共享工作流。
2. **事实可信。** 未知计数、未知时间、发现失败、读取失败和部分结果必须显式呈现。不把未观察到的数据当成不匹配、零或空会话。
3. **Agent 可用。** 每个能力都有稳定的机器可读输出：JSON 信封、明确的退出码、有界读取与续读游标、可校验的消息定位符。
4. **结果可追溯。** 导出和上下文片段保留 Session URI、正文 revision 与消息位置，使用者可以回到来源核对。
5. **单一原生可执行文件。** 通过 pip、uv、npm、curl、Homebrew、Scoop 分发同一个 Rust 二进制，运行时不依赖 Python、Node.js 或 Rust。
6. **兼容既有调用。** CLI 参数、默认路径、输出格式和退出码是公开契约。旧写法保留为别名，变更默认行为需要明确决定。

## 3. 非目标

- **不写入 Provider 数据。** 不修改、迁移、修复或恢复来源会话；不调用会触发上游迁移的接口。
- **不做云端同步或服务。** 不上传会话，不提供常驻服务、Web UI 或多用户共享。落地页的示例只使用虚构数据。
- **不复刻 Provider 私有格式。** raw 导出是标准化后的记录，不是来源备份，也不是可导回原工具的文件。附件实体和私有字段不保证全部输出。
- **不提供库 API。** 不发布 Python 导入 API、Rust crate 或插件机制；集成方式是子进程调用 CLI 并解析 JSON。
- **不内置 Agent 能力。** `--emit-prompt` 和 `--read-prompt` 只生成说明和命令，不代替外部 Agent 执行。内置 Collect 只调用用户配置的模型完成汇总，不扩展为通用对话或自动化工具。
- **不追求 Provider 的完整功能覆盖。** 只读取会话展示所需的数据；加密库、桌面端私有存储、已删除或回退的内容按需单独评估。

## 4. 设计原则

### 4.1 数据边界

- Provider 会话源只读。工具自己的索引、配置、日志和导出只写入本项目拥有的路径或用户指定的输出目录。
- 导出使用临时文件与原子替换，拒绝写入来源目录和目标符号链接。
- 测试和性能评估只使用隔离的合成数据，不读取真实用户目录。

### 4.2 职责单一归属

- Provider 私有 schema 只由该 Provider 解释。共享工作流只依赖 Session facts、标准化正文和 Provider 契约。
- 同一事实只有一个来源：列表、head、统计和筛选投影相同的消息数、模型和时间。
- 依赖方向固定为 CLI → core。core 不依赖终端、参数解析或 LLM 客户端。

### 4.3 语义一致

- 查询、搜索、阅读器和 Collect 共用同一套匹配与日期语义。索引只是加速手段，语义必须与进程内匹配等价，失败时回退。
- 搜索只匹配逻辑语料：标题、正文、推理和工具状态。JSON 转义和 Provider 私有元数据不是搜索语义。

### 4.4 有界与可恢复

- 读取、导出和汇总按预算分页或分块，不静默截断。超出预算的内容通过游标继续，或明确报告遗漏。
- 单个会话或 Provider 失败不影响其他结果，但必须进入诊断和部分结果标记。
- 缓存只保存派生数据，并随来源变化失效；不能恢复已删除或已过期的正文。

### 4.5 克制扩展

- 新能力优先复用现有契约和模块，不为假设的需求增加抽象、参数或依赖。
- 只在可观察行为变化、修复回归或保护高风险边界时增加测试。
- 性能优化需要配对测量，并验证输出与优化前一致。

## 5. 判断新需求

提交设计或 PR 前，逐项确认：

1. 是否需要写入 Provider 数据，或把用户数据发送到用户未配置的地方？需要则不做。
2. 是否让共享层解释某个 Provider 的私有字段？需要则改为扩展 Session facts 或 Provider 契约。
3. 是否改变现有参数、默认值、输出格式或退出码？改变则需要明确决定，并同步测试、README 和 skill recipes。
4. Agent 能否通过 JSON 和退出码可靠地使用该能力，包括失败与部分结果？
5. 能否用现有模块完成？新增模块、依赖或参数需要说明不可替代的理由。
