# 阅读器重绘优化

原阅读器每次重绘都会重新编译当前查询，并拼接、扫描整条命中消息来定位高亮行；列表项还会复制所有会话的标题和说明。本次缓存当前命中的展示行，在重新搜索、布局或工具详情变化、切换命中时刷新；普通重绘读取缓存，并借用已有列表文本。

只保存一个命中行位置，不预计算全部命中，也不缓存历史会话。高亮定位在普通重绘中的工作从 O(当前消息长度) 降为一次读取；整个重绘仍包含列表项构造、可见行处理和终端缓冲区更新。

## 测量方法

- 基线 commit：`4ed3e8e55fbd6a353ec97e75261cd0a296c109a8`，只给 `eaf026d67ff6b2db3afcd40d7b800ca931d241d1` 增加相同的手动基准。候选为本 PR 的性能修改。两份基准函数源码逐字相同，release 测试二进制摘要保存在原始数据中。
- macOS arm64、Apple M1 Pro、Darwin 27.0.0、Rust 1.90.0，使用 Ratatui `TestBackend` 的 100×24 终端缓冲区。输入在内存中构造，进程使用隔离环境，不读取 Provider 数据。
- 三种输入：128 字符前缀与一个会话、相同消息与 1,000 条会话列表、8 Mi 字符前缀与一个会话。前缀均为 ASCII `x`，随后追加换行及 `needle`；搜索命中放在可视区域。
- 来源解析、数据构造、查询、换行布局和跳转均不计时。每批先重绘 5 次，再计时重绘 200 次，除以 200 得到该批平均耗时。每份二进制先预热一批，再交错测量 7 批。
- 每批必须找到预期命中并显示 `needle`；完整终端缓冲区（包含文字、颜色和样式）的摘要必须在两个版本及重复样本间一致。只排除耗时字段后比较基准输出。
- 不与其他构建或测试同时测量。不包含真实终端 I/O、会话发现、首次打开或翻页读取，不能解释为整个阅读器流程的加速比。

## 结果

单位为毫秒，展示各批平均重绘耗时的中位数，括号是各批平均值的最小值至最大值，不是单帧延迟分布。

| 场景 | 基线 | 候选 | 基线 / 候选 |
| --- | ---: | ---: | ---: |
| 小消息、1 条会话 | 0.19287 (0.18745–0.20157) | 0.13502 (0.13076–0.13939) | 1.43× |
| 小消息、1,000 条会话 | 0.35976 (0.35053–0.36795) | 0.23197 (0.22374–0.23641) | 1.55× |
| 大消息、1 条会话 | 2.28908 (2.19111–2.34893) | 0.13252 (0.12982–0.28835) | 17.27× |

候选的大消息场景有一个较高样本，全部保留在原始数据中。结果说明本轮重绘消除了对整条消息的重复处理，不代表跨机器显著性或首次搜索、跳转、窗口缩放都获得同样收益。

行为验证覆盖宽窄窗口、工具内容展开与收起、清空搜索，以及真实 PTY 中缩放后跳转到下一个命中；保留终端恢复、会话切换、复制和导出检查。手动基准在常规测试中标记为 ignored，由下面的命令显式执行，不添加耗时断言。

## 复现与原始数据

分别在基线 commit 和本 PR 构建 release 测试二进制，每次将 `compiler-artifact.executable` 指向的文件复制到独立路径，避免后一次构建覆盖前一次：

```bash
cargo test --locked --release --bin agent-dump --no-run --message-format=json
uv run python scripts/benchmark_reader_redraw.py \
  --baseline /path/to/baseline-test-binary --candidate /path/to/candidate-test-binary \
  --repeats 7 --output dist/benchmarks/reader-redraw.json
```

脚本通过 `--ignored --exact terminal::reader::tests::benchmark_reader_redraw --nocapture` 执行相同基准。脚本 SHA-256：`823391905d7918bf319253d54b5c74c221195326bb90aa3e82bd7a1aded08ac2`。

[完整原始样本](reader-redraw.json)仅规范化二进制路径，保留所有耗时、输入参数和终端缓冲区摘要。
